# Flatsat hardware-in-the-loop rig

The rig is the PVDX-flatsat-hil repo, a submodule of PVDX at `flatsat-hil/` (`git submodule update --init
flatsat-hil`). Paths starting `tester/` or `hil/` below are in it; `src/...`, `make` targets and `make dev` are PVDX's,
run from the PVDX root. Commit rig changes in the submodule, then the new submodule commit in PVDX.

Read `flatsat-hil/hil/README.md` first: it has the wiring, the logic analyzer channel map and what each test covers.

## Pieces

- `tester/`: bare-metal firmware for the main tester (Metro M4 Grand Central, same ATSAMD51P20A as the flatsat).
  - Talks to the host over SEGGER RTT channel 0 (`platform.c`, PVDX's `src/misc/printf/SEGGER_RTT.c`) through a
    second J-Link on its SWD header. It disarms its outputs after 10 s without a command; `tester.py` keeps it alive.
  - `tester/ASF/` is generated by Atmel START from the project in `tester/tester.atzip` (configuration also in
    `tester/atmel_start_config.atstart`): clocks, TCC and TC PWM, DAC, ADC1, the S-band SPI slave, self-test bus
    masters, LED. Change it in START (load `tester.atzip`), export, and replace `ASF/` and `tester.atzip`; don't edit
    it by hand. START miscalculates DPLL0 as 360 MHz, so the Makefile passes the real 120 MHz frequency constants.
    START's SPI slave defaults to CPHA 1; `buses.c` sets mode 0 at startup.
  - The one register-level part is the two I2C targets the flatsat talks to (`i2c_slave.c`, with `sercom.c` for
    SERCOM3/6 clocks and interrupts): they decide ACK/NACK per address, produce each read byte on demand and can hold
    the bus, which ASF's I2C slave driver can't. Pin allocation is in `ASF/atmel_start_pins.h`, `tester/src/board.h`
    (ASF PINMUX_ values) and `analog_out.c`.
  - Bus bindings: `buses.c`. Device models (in `common/`): `stxg2_model.c`, `pmb_model.c`, `mcp23017_model.c`,
    `ina226_model.c` + `pixel_model.c`.
  - Host commands: `common/cmd.c`, documented in `hil/lib/tester.py`.
- `hil/lib/`:
  - `tester.py` (client: RTT through the tester's J-Link)
  - `rtt.py` (RTT by direct memory access; tells the two J-Links apart)
  - `flatsat.py` (one pylink session: reset, RTT log)
  - `logic.py` (sigrok-cli captures as VCD)
  - `models.py` (thermistor, photodiode and pixel physics, with constants parsed from the firmware sources)
  - `firmware.py`
- `hil/tests/`: one file per area. Behaviour the firmware doesn't have yet is `xfail` with the TODO it waits on.
- `tester/common/`: the device models and command parser, behind `tester_platform.h`, so they build and test on a
  host. (A reduced Uno R4 Minima tester built on them is in `git stash list`, "Uno R4 Minima flatsat tester".)
- The flatsat's digital outputs (magnetorquers, heaters, burn, S-band EN/RST) are only watched by the logic analyzer,
  never by the tester.

## Build and flash

```bash
make tester                                     # tester/tester.elf
make tester_flash JLINK_SERIAL=<tester probe>   # needs the user's approval, like any flash
```

Without a J-Link, `make -C tester flash_uf2` copies `tester.uf2` to its UF2 bootloader drive (double-tap its reset
button first, or `Tester().enter_bootloader()` from a running tester).

Pass the tester's probe so the flatsat is never flashed by mistake. Ask before flashing anything.

## Run

The suite resets the flatsat through the J-Link many times, which needs the user's approval like any reset. It never
flashes. Only one session per J-Link at a time: stop `tools/jlink.sh` and `tools/rtt.sh` first. The suite expects a DEVBUILD
flashed with `make flash_to_mram` from the tree whose `src/PVDXos.elf` it reads.

```bash
make hil                                              # or: cd flatsat-hil/hil && python3 -m pytest
cd flatsat-hil/hil && python3 -m pytest -m selftest   # tester alone, with the self-test jumpers (hil/README.md)
```

Builds the tests ask for, through `make dev DEFINES="..."` (src/Makefile):
- burn sequence: `BURN_SEQUENCE_FIRE_BURN_WIRE BURN_WAIT_MINUTES=2 BURN_ON_FOR_SECONDS=5`
- UHF beacons: `BURN_SEQUENCE BURN_SEQUENCE_UHF_MODE=BURN_UHF_MODE_BEACON POST_BURN_STEP_MINUTES=1`

## Adding an emulated device

1. Pick free SERCOM pads or pins against the Grand Central pin map, and add them to `tester/src/board.h`.
2. Write the model in `tester/common/` as start/write/read/end callbacks, and connect them in `tester/src/buses.c`
   They run in bus interrupts, so keep them short.
3. Expose its state and faults in `common/cmd.c` and `hil/lib/tester.py`.
4. Add a `-m selftest` check with the self-test bus masters in `selftest.c`.
5. Add the wiring to `hil/README.md`.
